# 手机助手（volumeswipe）

**一个用语音控制视频 App 的 Android 无障碍小工具。** 说一句话，它帮你暂停/播放、翻下一集、跳过广告、调音量、调亮度、打开 App。

不用 root，不用连电脑，**只需要打开无障碍服务**。

| | |
|---|---|
| 应用名 | 手机助手 |
| 包名 | `com.example.volumeswipe` |
| 版本 | 2.37（versionCode 57） |
| 系统 | Android 7.0+（minSdk 24），targetSdk 34 |
| 架构 | **只含 arm64-v8a**（近几年的手机都是，老 32 位机装不上） |
| 体积 | 约 56 MB（里面打包了 65 MB 的中文语音识别模型 + 11 MB OCR 引擎） |
| 下载 | https://github.com/yowper/volumeswipe/releases （每个版本一个 APK） |

## 一、装好后按 ①②③④ 走一遍

打开 App，主界面上从上到下就是这四步：

| 步骤 | 按钮 | 作用 |
|---|---|---|
| ① | 允许后台运行（忽略电池优化） | 不点它，MIUI / 鸿蒙 / ColorOS 过一会儿就把服务杀掉 |
| ② | 授予悬浮窗权限 | 屏幕上要显示那条小命令条 |
| ③ | 打开无障碍设置并开启本服务 | **核心**，没这个什么都干不了 |
| ④ | 开启后台常驻服务 | 通知栏出现「手机助手 · 运行中」，进程优先级提到最低 |

另外两个可选：

- **☀ 允许修改系统设置** —— 只有说「亮 / 暗」调屏幕亮度才需要，点它跳到系统页把开关打开。
- **▶ 测试Mic（标定麦克风位置）** —— 如果手动框弹出、豆包键盘出来了却没开始听，点这个：程序弹出键盘后，你**手点一下键盘上的麦克风按钮**，它就把你点的位置记下来（默认 32%, 66%），以后自动点。

再去系统设置里放行三项（每个 ROM 名字不同，意思一样）：**自启动**、**后台弹出界面 / 后台运行**、**电池无限制**。

## 二、识别路线与「手动」命令框

「豆包识别」开关（v2.30 起主界面勾选框已去掉）由语音切换：说「打开豆包」＝开（并立刻弹键盘叫出豆包）、「关闭豆包」＝关、「豆包」＝切换。**默认关**（本地直接听命令）。

### 「手动」命令框（v2.36 定稿，主推用法）

```
说「手动」
  → 屏幕弹出黑色小编辑框 + 抢焦点 + 等 200ms 弹键盘
  → 探测到豆包键盘真的弹出来了，才自动点一次它的麦克风（默认 32%, 66%）
  → 你对豆包说话（命令进框）或手动打字，想多长多短都行
  → 【没有任何超时/自动关闭】，框一直开着、不失焦
  → 再说一声「手动」→ 等框里文字稳定（≤1.5 秒）→ 关框并执行框里的命令
```

- 开框期间本地引擎**只听「手动」**这一个词——你说的话全交给豆包写进框，不会被本地抢先执行
- 执行前自动清洗框里内容：**去掉标点**、**去掉混进去的「手动」两个字**（说结束时豆包常把它也写进框），清洗后匹配命令表
- 开框 3 秒内的「手动」当回声忽略（防同一声被识别两遍把框秒关）
- 只在普通模式有效（短剧/阅读模式里说「手动」不接收）

### 不开豆包（默认，纯本地）+ 直接喊命令

v2.37 起**没有唤醒词了**（「嗨小白/小白」已整个删除）：本地语音引擎（Vosk 中文模型，已打进 APK）直接听整个命令表，听到命令就执行（只收 8 个字以内的短句，长句当视频里的话不理）。

```
停    放    下一集    上一集    上页    下页    广告    直播
大    小    亮    暗    抖音    红果    打开豆包    关闭豆包    小白再见
```

### 4.1 只认这份命令表（重要）

**不在上面表里的话，一律不执行，也不在屏幕下方显示**（只写进日志，方便你查它到底听成了什么）。

还额外做了三层收紧：

| 收紧 | 例子 |
|---|---|
| 单字命令（`停` `大` `小` `亮` `暗`）必须**整句就这一个字** | 说 `停` ✓；说 `停下来看看` ✗（不执行） |
| 不再是「≤ 4 字里含亮/暗/大/小 就算」 | 说 `真亮` `好暗啊` `很大` ✗（不执行） |

单字命令**还要有视频/声音在播**才执行（没在播就只听不动作）；
被拦下的都会写进日志，写明拦的原因。

### 4.2 上滑 / 下滑只滑一次（重要）

不管哪条命令，**上滑/下滑都只滑一次，不会连着滑好几次**：

- 滑动类命令（`下一集` `上一集` `广告` `直播`）**3 秒内只滑一次**：
  刚滑过又听到同一类命令 → 只写日志「不再滑第二次」
- 手势层面还有一道硬锁：**两次上滑/下滑至少隔 0.9 秒**（不管是哪条路径叫的，包括摇一摇、耳机音量下调两次）
- 广告/退出直播：**上拉前已经截图比较确认无秒了，就只拉这一次**（不再核对、不再补滑）

### 防止识别抖动（自动，不用管）

- 同一条命令 **1.5 秒内只执行一次**；上滑/下滑类命令（下一集/上一集/广告/直播）**3 秒内只滑一次，绝不连滑**（另有一道 0.9 秒的手势硬锁）
- v2.37 起没有唤醒词了，「小白」相关只保留**「小白再见 / 再见小白 / 小白拜拜」彻底退出**这一个意思
- 成对命令（大/小、上/下、亮/暗…）**3 秒内不许反着再来一次**（否则本地引擎会把「声音大一点」听成「声音小」）
- **一个字的命令（`停` `大` `小` `亮` `暗`）只在真的有视频/声音在播时才执行**：
  视频停了、或者页面上根本没在放的时候听到一个单字，只会写一条日志、不动屏幕（日志：`听到了「停」，但没执行：现在没有视频/声音在播`）
  （**摇一摇**也是同一个标准：没在播就不动手）
- **单字「放」已经去掉**：太容易在台词里被触发（“放假/放下/放松”…）。要暂停说 `停`/`暂停`，要播放说 `播放`/`继续`/`放着`/`放一下`
- 每条被拦下的都会写进日志，写明拦的原因

## 四、「退出广告 / 退出直播」是怎么做的

视频 App 的界面文字**读不到**（无障碍窗口列表里只有输入法和我们自己的悬浮条），所以全程靠**截屏 + OCR**：

1. **先静音**（用户要求：广告/直播动作不出声；**上拉发出后才恢复音量**。之前已经手动禁音的话就不重复禁）
2. **截图**（Android 11+ 的无障碍截屏，1 秒最多一次，**不需要**「录屏授权」这个弹窗）
3. OCR 只读**屏幕最下方 20%**，找 `N 秒`（那句「🔒 10 秒后可继续看下一集」）
4. **有秒就等：读到 N 秒 → 等 N 秒**（v2.19 起不减 1 秒，用户要求；宁可晚点也不能早滑白滑）。
5. **上拉之前【再截一张图】确认真的没秒了**（无秒 / 跳秒结束 / 延时到点，都走这一步）：
   - 再截图**还能读到 ≥ 2 秒** → 读秒没走完（或又跳回来了）→ 继续等
   - 再截图**读到 1 秒或读不到** → 确认没秒了 → **这时才上拉**
6. **就上拉这一次，上拉发出去之后才恢复音量**，滑完立即收尾：
   - 用户定稿：广告/退出直播**只能有一次上拉**。上面已经截图比较过、确认无秒字样，所以不再核对、不再补滑（拉多次是不对的）
   - 音量恢复值（v2.33 定稿）：**语音「广告」/摇一摇触发 → 恢复到禁音前的原音量（不加一）；蓝牙下键触发 → 恢复到按下前的值（相当于 +1）**

全过程会在**屏幕下方（读秒行上面一点）显示一条黑色状态条**，每一步都写出来：

```
听到「广告」→ 退出广告
退出广告：先禁音（上拉后自动恢复音量）
退出广告：已静音，不点暂停，直接截屏读读秒（屏幕下方 20%）
退出广告：读到读秒 10 秒 → 等 10 秒后上滑
退出广告：按读到的 10 秒（实际等 10 秒）延时结束 → 再截一张图确认没有读秒
退出广告：再截图确认没有读秒了，上滑
退出广告：确认没有读秒 → 上滑（只滑这一次；滑完恢复音量）
退出广告：上拉完成，恢复音量
退出广告：完成（上滑 1 次）
```

> 为什么不弹 Toast：Toast 一定出现在屏幕最下方，正好盖住读秒那一行，
> 而且会被截屏拍进去、干扰 OCR 判断读秒。所以广告/直播这两条命令改用自己画的状态条：
> 位置在屏幕 79% 处（底边留出 21%）、3 秒后自动消失、不抢触摸。
> 它也没进 OCR 区域（最下方 20%）和像素比对区域（最下方 12%）。

日志会把每一步写清楚：`已静音，不点暂停，直接截屏读读秒` / `读到读秒 10 秒 → 等 10 秒后上滑` / `延时结束 → 再截一张图确认没有读秒` / `上拉前恢复音量` / `确认没有读秒 → 上滑（只滑这一次）` / `完成（上滑 1 次）`。

**「退出直播」就是「退出广告」＋一个左划**：左划完成后直接调
`startSkipSequence("退出直播")`，和 `startSkipSequence("退出广告")` 是同一条代码路径 ——
左边那一步之后的静音 / 截图 / 读秒 / 上拉前恢复音量 / 只上拉一次，
两条命令一模一样。（状态条上会写一行：`退出直播：左划完成 → 接下来和「退出广告」完全一样`）

`暂停/播放 (50%,20%)`、`上页 (15%,85%)`、`下页 (85%,85%)`、`上滑 (50%,75%→25%)`。

### 摇一摇（主界面勾选，默认开；**只在短剧模式里起作用**）

摇一下手机 ＝ **广告命令全流程**（v2.32 起和蓝牙下键同款：先静音 → 截图读秒 → 只上拉一次 → 上拉后恢复原音量，不加一）。

三道门槛，防误触：

1. **短剧模式开着才行**：没开短剧模式时摇了什么都不做，只记一行「摇一摇忽略了：短剧模式才起作用（说「短剧」开启）」
2. **不用用力摇**：900ms 内凑够 **3 个超过 2.2g 的峰**就算一次真摇（用户要求降门槛，以前是 2.6g 太费劲）；
   拿手机、放手机、通知振动一下仍然不会触发（还要 3 个峰 + 冷却）
3. **只有真的视频/声音在播时才动手**（和单字命令同一个标准）：
   没在播的时候摇了什么都不做，只记一行「摇一摇忽略了：现在没有视频/声音在播」

正在识别命令（框/键盘在身上）时也不响应。

### 蓝牙耳机：音量上键 / 下键（v2.33 定稿）

手机音量键双击那条命令已**删掉**。改成**轮询媒体音量**（每 100ms 读一次），按一下就触发：

| 模式 | 音量**上键** | 音量**下键** |
|---|---|---|
| 短剧模式 | **播放/暂停**（点 50%,20%）+ 音量 −1 补回上调前 | **广告命令全流程** + 恢复音量时 **+1 还原到按下前** |
| 阅读模式 | **上一页** + 音量 −1 补回 | **下一页** + 音量补回（至少补到 1） |
| 普通模式 | 只调音量 | 只调音量 |

- 恢复值规则（v2.33 用户定稿）：**语音「广告」/摇一摇 → 恢复原音量不加一；只有蓝牙下键那轮 +1**（因为按下键时系统已经把音量 −1，+1 才等于回到原音量）
- 正在识别命令时不响应；上滑只滑一次的锁、防重都照常生效
- 排查看日志：蓝牙连着时每 10 秒一条「音量监视心跳：当前 X（蓝牙已连…）」；
  按键时记「音量采样：X → Y（下调/上调）（蓝牙已连）」。
  如果按了耳机音量键、日志里音量数字【不变】，说明耳机没把音量变化同步到手机
  （耳机是相对音量模式）：去手机「开发者选项」里关掉「禁用绝对音量」再试；
  程序只能看到手机这边的音量变化

## 六、短剧模式（🎬）与录制模式（🔴）

### 6.1 短剧模式：说「短剧」开关，开了只认这几条 + 自己录的命令

**没有勾选框，和「豆包」一样用语音切换**：说一声 `短剧` ——

- 没开 → **进入短剧模式**；开着 → **退出短剧模式**（恢复接收所有命令）


短剧模式开着时（v2.32 起只收这几条）：

| 说的 / 按的 | 结果 |
|---|---|
| `停` `暂停` `播放` `继续` `继续播放`… | ✓ 接收（在 50%,20% 点一下） |
| 蓝牙耳机**上键** | ✓ **播放/暂停** + 音量 −1 补回 |
| 蓝牙耳机**下键** / 摇一摇 | ✓ **广告命令全流程**（下键恢复音量 +1 还原；摇一摇恢复原音量） |
| `声音大` `声音小` `禁音` `声音` 等 | ✓ 接收（调音量/禁音/恢复） |
| 自己录的命令（如 `点赞`） | ✓ **照常接收**（录的就是拿来退广告的，见 6.2） |
| `短剧` | ✓ 再说一次就退出短剧模式 |
| `小白再见` `再见小白` `小白拜拜` | ✓ 还是能彻底退出（留的安全阀） |
| 其他（`下一集` `上一集` `广告` `直播`、单字 `大` `小` `亮` `暗`、`打开微信`、`手动`、`录制`…） | ✗ **一律不接收**：不执行、屏幕下方也不显示，只在日志里写一行为什么不收 |

日志会写成这样（“听到了什么”和“为什么拦”都能看到）：

```
20:11:07  短剧模式已开启：语音「短剧」
20:11:40  听到：「停」→ 命令：停 / 继续播放（点 50%,20%）
20:11:40  已执行：停
20:12:03  短剧模式已关闭：语音「短剧」
20:12:30  蓝牙耳机音量下调了一下 → 广告命令，恢复时音量 +1 还原到 11
20:12:31  已退出：短剧模式也自动关闭了
```

### 6.2 录制模式：说「录制」→ 做动作 → 再说一声「录制」→ 起名保存

**开始**：用语音说 **`录制`**（或主界面点 **🔴 录制动作** →「▶ 现在就开始录制」）。不用先起名字。

**做动作**：直接在要操作的界面做 ——

- **录制时每个动作都会【真的执行】**：浮层把你的触摸接住记下来，
  同时立刻原样转发给系统 —— 点哪点哪、滑哪滑哪，上滑 / 左滑都照常生效
  （转发是一个接一个发的，动作之间会有一点肉眼几乎看不出的延迟）
- 轻点一下 = 记一个「点击位置」；按住拖动 = 记一条「划动」（起点 / 终点 / 划了多久；上滑/下滑/左滑/右滑在浮条里分别计数）
- 录制时【真的会点/真的会滑】（v2.23 修：转发动作的瞬间浮层临时不挡触摸，动作真正落到应用上；以前只记到第一步就是被浮层挡了）
- 两步之间的间隔最长记 8 秒（v2.23 起从 4 秒放宽），重放时按原间隔做
- 两个动作之间隔了多久也一起记（最长按 4 秒算）
- 屏幕最下面只显示一条小字「🔴 录制中：已记 N 步」（v2.22 起去掉了原来的大黑框和三个按钮——
  用户反馈挡住屏幕没法录）；点错了没有撤销按钮：点错就整段重录，
  或者录完在主界面的「录制动作」弹窗里管理：每条命令都有「删除」和「改名」
  （v2.25：名字能改了——语音识别不准没关系，起的名随时改）；
  录制保存时弹框里的文字是白字黑底，看得清

**结束**：再说一声「录制」或「录制结束」→ 弹出文本框 → 起一个语音命令名 → 「保存」。
（v2.20 起不再用双击屏幕——有的手机双击=截图；v2.22 起也不再有「完成」按钮，全靠语音结束。）

**使用**：以后说这个名字 → 程序按录制的顺序重做这串动作：**按录制间隔，每步额外多等 0.2 秒、相邻动作至少隔 0.3 秒**
（用户要求动作之间要有一定的延时，页面动画才来得及走完）。

注意：

- 名字最好 **2 个字以上**（单字容易被视频台词撞上）；名字会自动进本地识别词表，说得出就听得懂
- 同一个名字再录一次 = **覆盖**旧的那串动作；主界面弹窗里能看到已录的命令（几步 / 约几秒）+ **删除**
- **短剧模式里自己录的命令照常能用**（就是拿来退广告的）
- 一次重放 **3 秒内不会来第二遍**（防本地识别抖一下就连做两次）
- 因为**双击被拿来当结束**，录制过程中没法录「双击点赞」这种动作（要录的话告诉我，改成别的结束方式）

## 七、日志 / 提示在哪看（排错必备）

1. **屏幕下方状态条**：听到命令、以及「退出广告/退出直播」的每一步（读到几秒、上滑第几次、有没有生效）都会写在这上面，3 秒后自动消失
   （**不在命令表里的话不会显示**，但会写进下面两处日志）
2. **通知栏**：常驻通知「手机助手 · 运行中」——不展开能看到**最近 3 条**，展开是**最近 5 条**（带 `HH:mm:ss` 时间）
3. **主界面**：中间那个 **📋 查看最近日志（排错用）** 按钮，弹出可滚动的完整日志

日志不只记录「执行了什么」，也会记录**听到了什么**：

```
14:02:31  听到：「下一集」→ 命令：下一集（上滑）
14:02:31  已执行：下一集
14:02:35  听到：「今天天气不错」→ 不在命令表里（不执行、不提示）
14:02:40  豆包输入框里的字：「广告」
14:02:40  听到：「广告」→ 命令：退出广告
```

出问题把这两处的文字发出来就能定位。

## 八、后台能不能一直跑

**无障碍服务是系统托管的，不是 Activity 的附属**。把 App 从最近任务里划掉，服务通常照样活着。

真正会停掉它的只有三种情况：

| 情况 | 结果 | 处理 |
|---|---|---|
| 被 ROM 省电策略回收 | 服务静默丢失 | 开 ①（电池优化白名单）+ ④（常驻服务） |
| 手动「强行停止」 | 无障碍开关会被系统强制关闭 | 用 App 内的 ⑤ 退出，别用系统那一项 |
| 重启手机 | 无障碍服务由系统自动恢复 | 不用管（`onServiceConnected` 里会自动把常驻服务拉起来） |

本工程做的加固：前台常驻服务（带低优先级通知）、电池优化白名单入口、开机自动恢复、主界面三行状态自检（无障碍 / 常驻服务 / 电池优化，哪项掉了直接点对应按钮）。

**本地语音跑久了不灵的自愈（v2.22 加强）**：看门狗每 2.5 秒查一次——引擎没了会自动重启；
麦克风被某段流程暂停后忘了恢复（以前要重进 App 才好）连续 5 秒就强制恢复；
命令状态卡住超过 2 分钟没结束也会强制复位回待命，语音重新听。

### 怎么退出

点 ⑤ 退出（或说「小白再见」）：

| 做了什么 | 下次怎么恢复 |
|---|---|
| 写 `enabled=false`、自动关短剧/阅读模式、收掉所有悬浮框（含手动命令框）、**暂停采音**（通知变成「已暂停」）。**无障碍开关和常驻服务都保留**（v2.30 起：服务整个停掉的话，有的手机会把无障碍开关也一起关） | 重新打开 App 自动恢复 |

为什么不去关无障碍？`disableSelf()` 是单向的——Android 不允许程序自己把无障碍开关**打开**，关了就必须用户去系统设置里手动开，所以干脆永远不关。

## 九、常见问题

- **说「手动」后键盘出来了，但豆包没开始听**：Mic 坐标没对上。点 **▶ 测试Mic**，程序弹出键盘后你手点一下麦克风按钮，它会记住位置（默认 32%,66%）。
- **说「亮 / 暗」没反应**：需要主界面 **☀ 允许修改系统设置** 授权（状态栏会写「未允许 ✗ 请点 ☀」）。部分 ROM 开着自动亮度会覆盖，程序会顺手把自动亮度关掉。
- **某条命令老是自己乱触发**：`停/放/大/小/亮/暗` 是单字命令，只有**视频/声音在播**时才会执行（没在播就只记日志、不动屏幕）；`广告/直播` 是两个字的，仍然可能被视频里的话命中。告诉我哪条乱触发，我把它限制得更严。
- **「退出广告」滑了但页面没变**：上拉前会先截图比较确认读秒已经没了才拉；如果日志里写的是「再截图确认还有 N 秒」→ 说明读秒真没走完，它又接着等了（**不会连着拉好几次**）。把日志发我。
- **通知栏没有「运行中」那条**：点 ④。Android 13+ 首次要允许通知权限。
- **生僻名字（红果 / ds / 天鹅）本地识别听不准**：本地模型缺少 `graph/words.txt`，无法做动态语法，现在是自由识别状态。这种情况说「手动」打开命令框用豆包 Mic 说最准。
- **装不上 / 闪退**：APK 只含 arm64-v8a，32 位老机器装不上。

## 十、自己编译

### 云端（推荐，本地不用装任何东西）

本工程自带 `.github/workflows/build.yml`：

- **push 到 main** → Actions 自动编译，约 3~4 分钟 → 在该次运行的底部 **Artifacts** 下载 `VolumeSwipe-debug.zip`
- **推 `v*` 标签** → 自动编译**并挂到 Release**，别人可以直接下载

```bash
git tag -f v2.11 && git push origin refs/tags/v2.11 --force
```

> workflow 里没用第三方 `setup-android` action（实测在 runner 上会失败），而是自己用官方 `commandlinetools-linux-11076708_latest.zip` + `sdkmanager` 装 `platforms;android-34` 和 `build-tools;34.0.0`。

### 本地一键（`build_apk.bat`）

双击即可。构建工具链（JDK 17 / Android SDK / Gradle 8.7 / 语音包原始压缩包）统一放在 **`D:\apktools`**（v2.33 起和源码目录分离）：脚本先去那里找，没有就自动下载到那里。编译完把 `VolumeSwipe-debug.apk` 拷到桌面。

> v2.36 起本地和云端用同一份 `release.keystore` 签名（进仓库），两边打的 APK **互相覆盖安装不用卸载**，无障碍设置不再被清零。

### Android Studio

`File → Open…` 选本工程目录 → 等 Gradle 同步 → 点绿色 ▶ 或 `Build → Build APK(s)`。

## 技术要点一览

| 需求 | 实现 |
|---|---|
| 模拟点击 / 上滑 / 下滑 / 边缘左划 | `AccessibilityService.dispatchGesture()`，失败自动补发一次 |
| 读屏幕下方读秒 | `takeScreenshot()`（Android 11+，无需录屏授权）+ ML Kit 中文 OCR，只读最下方 20% |
| 页面有没有变 | 截屏指纹比对（中间 20%~80% 灰度指纹），以及最下方 12% 的像素比对 |
| 本地语音 | Vosk `vosk-android:0.3.47` + 打进 assets 的中文小模型 |
| 豆包语音输入 | 弹出自己的输入框 → 抢焦点弹键盘 → 点豆包 Mic → 读框里的字 |
| 后台不死 | 前台常驻服务 + 电池优化白名单 + 无障碍服务系统托管 |
| 悬浮命令条 | `TYPE_ACCESSIBILITY_OVERLAY` 窗口，长按拖动记住位置，`FLAG_NOT_TOUCH_MODAL` 不挡下面的 App |
| 短剧模式 | 语音「短剧」切换（`CMD_DRAMA_TOGGLE`）；退出程序自动关；`AutoService.resolveCmd()`：所有语音路径都走这一个解析入口，v2.32 起只放行 停/暂停/播放 + 录制命令，蓝牙上键（播放/暂停）/下键（广告）/摇一摇（广告）不走语音解析直接触发 |
| 蓝牙耳机音量键 | 轮询 `STREAM_MUSIC`（100ms）：上键=播放/暂停+音量−1补回（短剧）/上一页（阅读）；下键=广告全流程+恢复音量+1还原（短剧）/下一页（阅读）；普通模式只调音量；程序自调音量 `markVolSelf()` 不当按键 |
| 广告/直播静音 | 流程开始 `muteForSkipFlow`（已在手动禁音就不重复禁，`skipFlowMuted` 记流程自己的），**全程不点 (50%,20%)**；v2.33 起改为**上拉发出去之后** `unmuteForSkipFlow` 恢复音量（蓝牙下键那轮恢复目标=按下前，其余=禁音前） |
| (50%,20%) 点击 | **只存在于「停/播放」命令**（v2.18 起豆包唤醒/恢复播放那套 `pausedByUs` 死代码全删，程序里其他地方不再碰这个点） |
| 摇一摇 | 只在短剧模式：900ms 内 3 个超过 2.2g 的峰（不用用力摇）= 广告命令全流程（和蓝牙下键同款，恢复原音量不加一）；非短剧模式只记日志 |
| 手动命令框 | 说「手动」开框（等键盘真弹出才点 Mic 32%,66%，点完 1 秒没动静补点一次）；开框期间本地词表切成只剩「手动」；再说「手动」等框内文字稳定（300ms×5）→ 清洗（去标点+去「手动」回声）→ 匹配执行；无任何超时/自动关闭，退出/切模式强制关框并还原词表 |
| 录制 / 回放动作 | 语音「录制」开始（`CMD_RECORD_TOGGLE`）→ 全屏透明浮层接住触摸记成百分比坐标 + 间隔，**同时立即原样转发给系统**（`dispatchGesture` 队列）→ 动作真的生效；说「录制」/「录制结束」结束（v2.20 删掉双击屏幕结束，避免触发手机的双击截图）→ 悬浮弹框起名保存；重放 = 按录制间隔 + 每步 +0.2s、相邻至少隔 0.3s |
